# ADR-0001：错题数据模型与长答案拆分

- 状态：Accepted
- 日期：2026（项目起始）

## 背景

错题本需要同时容纳：短答案（选 A / 一句话解析）与长答案（多步解题、公式、截图）。
产品要求长答案"点击后自动跳转答案页"。

## 决策

1. **一道错题 = 一条 Markdown 笔记**，元数据全部进 frontmatter（`id`/`subject`/`answerMode`/`maskStyle`/`status`…）。
2. 答案写在内联 callout `> [!answer]` 中，答案**默认与题目同笔记**。
3. 满足任一"长答案"条件时拆分为**独立答案页**（`答案/<同名>.md`）：
   - 内容超过阈值字符（默认 400，可配）；
   - 含展示型公式 `$$…$$`（默认开）；
   - 含图片**默认不触发**（照片答案保留原地遮罩揭晓），可配；
   - frontmatter `answerMode: page` 手动强制。
4. 拆分后题目页的答案块替换为**纯 wikilink 占位**（指向答案页），点击即原生跳转；答案页顶部带"← 返回题目"链接与 `mt-answer-of` 反链。
5. 拆分操作是**源码级变换**（replace + 新文件），不动用户其余内容；提供"拆分当前笔记"命令，未来提供反向合并。

## 备选与取舍

- 全部答案独立成页：结构最干净，但短答案也要跨文件，录入负担大 → 放弃。
- 全部内联 + 全宽弹层：数据集中，但长答案编辑/检索体验差 → 放弃。
- 图片也强制拆分：与"截图答案原地马赛克揭晓"的产品诉求冲突 → 做成默认关闭的可选项。

## 代价

- 占位块形态下答案页与题目页各自独立，重命名题目文件会断链（Obsidian 内部链接改名会自动更新，可接受）。
- 需要维护"内联 ↔ 拆分"两种形态的一致性（未来用 `answerMode` 做反向合并）。
